# 공장 게임 프로토타입 개발 순서

- 작성일: 2026-11-05
- 기준: 게임 기획서 0.9, 아이템 기획서 0.2 및 이후 맵 구성 논의
- 상태: 구현 순서 제안이며 미정 기획을 확정하는 문서는 아님

## 1. 현재 상태와 첫 목표

저장소에는 기본 C++ 게임 모듈과 프로젝트 설정이 있으며, 별도 게임플레이 클래스는 아직 없다. Content 폴더에서 프로젝트 에셋 파일은 확인되지 않았고 기본 실행 맵은 엔진의 OpenWorld 템플릿을 가리킨다. 에디터 DLL 산출물은 존재하지만 이번 계획 작업에서 빌드·실행·패키징을 검증한 것은 아니다. 엔진 연결은 GUID이므로 이전 대화의 버전 대신 실제 연결 설치 경로를 구현 시작 시 확인한다.

첫 플레이 목표는 사용자가 채석장을 놓고 도로를 연결해 돌을 시작 항구로 보내면 돈이 들어오는 것이다. 처음부터 완성형 맵, 모든 자원, 철도와 발주를 동시에 구현하지 않는다. 작은 고정 맵에서 물류와 재투자 순환을 검증한다.

## 2. 첫 프로토타입의 작업 순서

### 0단계 개발 환경 확인

- 현재 엔진 연결 경로·버전과 C++ 도구 체인 확인.
- Development Editor 빌드와 에디터 실행 확인.
- 프로젝트 전용 테스트 맵 생성 후 Windows Development 패키징·실행 확인.
- 이후 기본 실행 맵을 이 테스트 맵으로 지정.

완료 기준: 에디터와 패키징한 실행 파일에서 같은 테스트 맵이 열린다. 기존 DLL 존재만으로 완료 처리하지 않는다.

### 1단계 카메라와 입력

- 캐릭터 없는 쿼터뷰 카메라 이동과 확대·축소.
- 마우스의 지면 위치 계산과 시설 선택.
- 기본 배속 및 일시정지의 공통 시간 기준 마련.

완료 기준: 테스트 맵을 이동하며 원하는 위치와 임시 시설을 선택할 수 있다.

### 2단계 격자와 건설

- 평지·수면·돌 노드·시작 항구가 있는 작은 고정 맵 구성.
- 격자 좌표, 건물 점유 칸, 설치 미리보기와 회전.
- 겹침·물 위·자원 노드 불일치 등 배치 불가 판정.
- 임시 자금과 건설비 차감, 취소 시 비용 미차감.

완료 기준: 돌 노드에 채석장을 건설하고 건설 가능한 위치와 비용을 확인할 수 있다. 칸 크기와 건물 크기는 조정 가능한 시험값으로 둔다.

### 3단계 재고와 생산 데이터

- 아이템·시설·제조법을 외형과 분리된 데이터로 정의.
- 제조법 입력 목록은 처음부터 3~4종도 표현할 수 있게 구성하되 첫 구현은 돌만 사용.
- 시설별 입력 재고, 출력 재고, 생산 상태와 임시 생산 시간 구현.
- 채석장 생산과 출력 저장소 포화 시 생산 정지.
- 시설 선택 화면에 현재 재료량·상품량·생산 상태를 표시.
- 시설과 운송에 사용할 고유 ID 및 저장 가능한 상태 구조 마련.

완료 기준: 채석장의 돌이 늘고 저장 한도에서 생산이 멈춘다. 수치는 데이터 수정으로 바꿀 수 있다.

### 4단계 도로와 경로 연결

- 직선·모서리·교차로의 도로 배치 및 연결 데이터.
- 시설 출입구와 도로 연결, 출발 시설의 목적지 선택.
- 목적지까지의 경로 탐색과 연결 불가 표시.
- 시설 정보에 공급 출처와 상품 목적지 표시.

완료 기준: 채석장에서 항구까지 경로를 찾고 끊어진 경로에서는 운송을 시작하지 않는다.

### 5단계 예약과 트럭 운송 및 판매

- 도착 저장소의 실제 재고와 입고 예약량 관리.
- 각 출고 건물은 1초마다 출고를 시도하고 적재량·재고·예약 가능량 중 가능한 물량만 출고.
- 트럭 구매·회송 없이 이동 화물 상태와 시각 차량을 생성하여 경로를 따라 이동.
- 입고 시 예약 해제와 실제 재고 전환, 시작 항구에서는 도착 즉시 한 번만 판매.
- 목적지 포화 시 출발 보류, 예외 초과 입고는 목적지 재고로 보존.

완료 기준: 채석장 → 도로 → 트럭 → 시작 항구 판매 → 돈으로 추가 건설이 이어진다. 유한 저장소 시험 대상으로 임시 수신 시설을 두어 예약을 검증한다.

### 6단계 공유 도로의 교통

- 차선별 이동, 앞차 간격, 교차로 통행과 합류 대기.
- 도로 출구가 막히면 새 트럭 출발을 보류하고 물품은 출발지에 유지.
- 출발 실패가 예약 누수나 나중의 일괄 차량 생성으로 이어지지 않도록 처리.
- 서로 다른 시설의 트럭이 같은 도로를 공유하는 상황 구성.
- 물량·차량 수·대기 시간을 관찰할 최소 진단 표시.

완료 기준: 혼잡한 도로의 납품량이 줄고 경로·진입로를 개선하면 회복된다. 한 목적지의 재고 포화가 관계없는 운송을 막지 않는다. 단순 교차 상황에서 영구 교착이 생기지 않는다.

### 7단계 단일 가공과 복합 생산

- 돌 → 석판, 원목 → 판재의 시험 체인.
- 석판과 판재를 사용하는 복합 상품 1종 추가. 석재 테이블은 임시 후보 이름.
- 재료 부족과 출력 재고 포화에 따른 생산 상태 표시.
- 출고 목적지 변경 시 진행 중 운송과 다음 출고 처리 구분.

완료 기준: 두 생산라인의 재료가 한 시설에 도착하여 복합 상품을 생산·판매한다. 이 시점에 첫 플레이 검증용 빌드를 만든다.

### 8단계 저장과 불러오기

- 자금, 시설, 도로, 재고, 생산 진행도, 목적지와 운송 중 화물 저장.
- 화물 ID와 예약의 대응 관계 복원, 도로 연결과 경로 복원.
- 저장 버전 기록과 데이터 오류 표시.

완료 기준: 운송 중 저장한 게임을 다시 열어 물품 손실·중복 입고·중복 판매 없이 이어간다. 이후 단계마다 새 상태를 저장 항목에 추가한다.

## 3. 첫 버전의 임시 규칙 제안

아래는 개발 착수를 위한 제안이며 정식 기획 확정과 구분한다.

- 직각 사각 격자, 건물 90도 회전, 평지 중심 고정 맵.
- 왕복 차선과 단순한 교차로 우선순위. 실제 차량 물리보다 도로 경로와 차간 거리로 이동 제어.
- 초기 시설당 출고 목적지 1곳. 여러 시설이 하나의 목적지로 공급하는 것은 허용.
- 입력 재료별 저장 한도와 출력 저장소 분리.
- 생산 시작 시 입력 재료와 완제품 공간을 확보하여 완료 시 초과 생산 방지.
- 내부 시뮬레이션 시간 기준 1초 출고, 일시정지 시 생산·운송 정지. 게임 하루 길이는 발주 구현 전 결정.
- 배송 중 목적지 철거와 사용 중 도로 삭제는 첫 버전에서 제한하고 이후 편집·복구 정책을 설계.
- 가격·건설비·제조 수량과 시간은 임시값. 균형 조정은 첫 플레이 이후.

## 4. 검증할 핵심 실패 상황

- 두 시설이 동시에 같은 목적지에 예약해도 공간을 중복 할당하지 않는다.
- 목적지 용량이 운송 중 줄어든 경우 초과분을 보존하고 신규 출발을 막는다.
- 도착 처리가 중복 호출돼도 재고와 판매 대금을 중복 지급하지 않는다.
- 재료 한 종류가 부족하거나 출력 공간이 없으면 생산하지 않는다.
- 빈 출발지·끊긴 경로·포화된 출구에서 잘못된 차량이나 예약이 생성되지 않는다.
- 배송 중 저장·불러오기 후 남은 재고, 운송 화물과 예약량이 일치한다.

## 5. 첫 프로토타입 이후 순서

### 9단계 창고와 유료 업그레이드 기반

창고 비축·출고 제어를 만들고 트럭 적재량·속도 업그레이드부터 적용한다. 업그레이드 가격과 효과는 데이터로 관리한다. 철도역·항구 관련 네 업그레이드는 해당 시설 구현 시 연결한다.

### 10단계 토지 구매와 절차적 생성

격자를 구역으로 묶고 미구매 지역의 안개, 구매 후 생성·공개, 비용과 소유권 확정을 구현한다. 고정 구역 두 개로 구매 흐름을 먼저 확인한 뒤 지형·자원 생성기로 대체한다. 월드 시드, 생성 버전, 기존 경계 연결과 필수 자원 접근 가능성을 검증한다. 구매 실패 시 결제만 남지 않게 처리하고 생성 결과를 저장한다.

### 11단계 최소 발주와 진행 목표

최초 품목으로 짧은 테스트 메인 발주 단계를 구현하여 일반 판매와 납품 배정을 구분한다. 중형 항구 업그레이드와 서브 발주를 추가하고 수락 하루·납기 하루를 별도로 처리한다. 게임 하루의 길이, 비축 제어, 실패와 보상 규칙을 이 단계 시작 전에 정한다. 하루 길이는 시험값으로 조정 가능하게 둔다.

### 12단계 원거리 물류

철도역 입구·출구, 10초 출고와 도착역 예약을 구현한다. 열차 전량 출고와 예약의 결합 방식은 기획상 기준안이므로 이 단계에서 확정한다. 신규 항구는 10초마다 모인 물량을 시작 항구로 운송하고 도착 시 판매한다. 철도역 기본 2개·신규 항구 기본 1개 한도와 건설 한도·저장량 업그레이드를 연결한다.

### 13단계 자원과 상위 생산 체인

석탄·철 이후 구리·석유·석영·금 계열을 데이터와 시설로 확장한다. 정유의 단일·복수 산출과 액체 운송 방식은 구현 직전에 결정한다. 3~4종 조합의 공급 불균형과 저장 공간을 검증한다. 업데이트 신규 자원이 미생성 지역에 반영되는 흐름도 확인한다.

### 14단계 최종 발주와 엔딩

완성된 생산 체인에 맞춰 메인 발주 단계를 확대한다. 최상위 제품 대량 납품으로 엔딩을 표시하고 동일 맵의 무한 플레이로 이어간다. 저장·불러오기 후 엔딩과 완료 보상이 중복되지 않게 한다.

### 15단계 반복 검증과 완성도 향상

경제 균형 조정은 첫 플레이부터 반복하고, 대규모 성능 측정은 공유 도로 단계부터 시작한다. 후기에는 확장된 공장 규모에서 최적화, 정식 모델·효과·사운드, 안내와 편의 기능을 보강한다. 단계별 Windows 빌드 검증을 이어간다.

## 6. 다음에 착수할 작업

0단계 개발 환경 확인 후 1단계 카메라와 2단계 고정 맵·건설을 진행한다. 당장의 결과물은 쿼터뷰에서 돌 노드를 보고 채석장을 설치할 수 있는 화면이다. 이후 생산·도로·예약·운송을 연결해 첫 판매를 완성한다.

기획서 9절에 남은 엔딩 미정 문구는 이후 확정된 10~11절의 메인 발주 완료 및 엔딩 후 무한 플레이 규칙을 우선한다. 원본 문서의 이 문구는 다음 개정 때 함께 정리한다.
